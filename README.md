# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 全量落成闸（canary-full-cutover-gate）

### 锁定策略（二选一，已敲定为乙策，全站贯彻）

**策略码 `EARLY_FULL_MARKED` —— 允许提前全量 · 未满百留标可核。**

金丝雀比例未满 100% 时允许点「全量放行」，但必须在**同一笔 SQLite 事务**内完成：

1. `releases.status → 已放行`（条件更新，仅 `已入闸/晋升中` 可落，rowcount=1 否则 409）；
2. 持久化未满百事实：`releases.early_full=1` + 全量时比例快照 `full_ratio=<当时 canary_ratio>`（**不回改比例真源** `canary_ratio`）；
3. 写全量回执 `cutover_receipts`（回执号 `QL<时间>-<单id>-<随机>`，含比例/标记/名册版本/切换实例数）与 `full_receipt_no`；
4. 推进名册 `app_env_versions` 到目标版本；
5. 产环境实例收敛：全部挂到目标版本/本单、`instances.traffic_ratio=100`（保留探针健康状态）；
6. 写审计：类别「全量」、动作「全量放行」，备注含 `30%` 等当时比例、未满百标与回执号。

任一步失败整笔回滚——**不存在「实例已全切但状态/回执没写成」的半提交**
（有故障注入 `{"故障注入":"全切后失败"}` 可验：接口 4xx，状态不变、无回执、无目标版本实例）。

互斥备选甲策 `HARD_REJECT_BELOW_100`（未满百整笔硬拒）**本站不采用**，仅在
`GET /api/全量闸策略` 中留档说明。无任何 `confirm()` 二次确认交互。

### 全站唯一的「全量完成定义」

发版单列表/详情、晋升写口（含 `目标环境=产`）、总览计数、对账结论、健康实例、
审计证据全部读同一组事实，经 `app/services/cutover.py:cutover_view()` 重放计算。

**切满探针（“已切满”的唯一定义）**：比例真源 == 100 且全量事件（回执 + 回执号）在
且名册一致 且产实例全切 且审计证据在 且无任何结构性缺口。比例 < 100 时（哪怕乙策下
合法留标）探针一律“未过线”，全量格只允许显示 `未满百全量` 并钉住 `切满差额`，
绝不点亮成 `满百全量`。**切满探针 ∪ 全量事件 ∪ 全量格 ∪ 审计证据同命运**：
全量回执可以先绿，但探针没过 / 比例未到百分百时一律钉缺口；
缺口未清不得把未切满标成已全量。写口在同一笔事务末尾用探针复核，未过线整笔退回。

| 对账结论 | 含义 |
| --- | --- |
| `全量一致` | 已放行 + 比例满百 + 未挂未满百标 + 快照==真源 + 回执==单子 + 名册一致 + 实例全切 100% + 审计在 |
| `未满百全量可核` | 已放行 + 比例<100 + `early_full=1` + 快照==真源 + 回执==单子 + 名册/实例一致 + 审计在（**合法态**，不假装金丝雀跑满） |
| `未全量` | 单子尚未放行 |
| `分裂·未满百无标` | 已放行且比例<100，但没有未满百标 |
| `分裂·满百仍挂未满百标` | 比例已满百，未满百标回滚不干净 |
| `分裂·全量快照与真源分叉` / `分裂·回执与单子分叉` | 快照 / 回执的当时比例或标记与真源比例不一致（**假全量回执**在这里被识破） |
| `半截·无全量回执` / `半截·无全量比例快照` / `半截·名册版本未切` / `半截·实例未全切` / `缺口·无实例挂接` / `半截·无审计证据` | 半写缺口 |

全量格取值：`满百全量`（探针过线）· `未满百全量`（有标的合法早全量，钉 `未满百差额`）·
`缺口·未全量`（结构性缺口）· `未全量`（未放行）。旁侧计数格（总览 `旁侧计数格`、
对账 `全量格对读`）与全量格**同源派生**，不允许各自拧花。

读侧每次从 releases / 回执 / 名册 / 实例 / 审计现存事实**重算**，可重放；
重放会补标 / 补切 / 揭穿并更正假全量回执（不回改真源比例），并写「全量重放」审计证据。

### 主要接口

```text
GET  /api/全量闸策略
GET  /api/发版单                     # 每行含 比例百分列/全量格/切满探针/切满差额/未满百全量/全量回执号
POST /api/发版单/{id}/金丝雀比例      # 别名 /比例；body 接 金丝雀比例|比例|canary_ratio
                                     # 已放行/已回滚/已关闭 → 400「…比例冻结…」
POST /api/发版单/{id}/全量放行        # 别名 /全量、/放行全量
                                     # body: {"备注":"", "故障注入": null}
                                     # 事务末尾切满探针复核，未过线整笔退回
                                     # 重复调用幂等：返回 幂等:true 并做重放收口
POST /api/发版单/{id}/重放收口
POST /api/发版单/{id}/晋升            # 目标环境=产 时委托同一个 execute_full_cutover，无旁路
GET  /api/总览                       # 策略 / 旁侧计数格 / 全量格对读 / 未满百全量[] / 分裂告警[] / 全量回执[]
GET  /api/对账                       # 全量对账[] / 全量对账汇总 / 全量格对读[] / 全量格对读汇总 / 金丝雀对账[]
POST /api/对账/重放                   # body {"发版单编号": id}；不带 id 批量扫全部已放行单
                                     # 别名 /对账/全量重放、/对账/修复
GET  /api/实例                       # 含 切流比例/金丝雀比例/全量格/切满探针过线/未满百全量/全量回执号
GET  /api/审计?类别=全量&动作=全量放行&关联编号={id}&关键词=...
```

并发：连接 `isolation_level=None` + `BEGIN IMMEDIATE`，配合 WAL 与
`busy_timeout=5000`，「并发改比例 vs 点全量」在库层串行，结局唯一且快照==真源。

### 页面面（定位面全覆盖）

- **总览** `/`：策略横幅、旁侧计数格（已放行/合法全量/未满百/满百/缺口/探针过线/分裂）、
  全量格·切满探针对读表（比例百分列、切满探针、切满差分、切满差额、全量格、全量事件、审计证据）、
  未满百全量明细、分裂告警、在途全量格与探针列、最近全量回执（含切满差额）。
- **发版单** `/发版单`：比例百分列 + 未满百/满百徽章、行内比例输入与「改比例」、
  建单比例字段、全量格列、切满探针列、切满差额列、回执号列、
  每行「全量放行」按钮（无确认框）、成功回执提示（显示全量格 / 探针 / 未过原因）。
- **晋升** `/晋升`：比例百分列 / 全量格列，选「产」走同一闸，另有行内「全量放行」。
- **对账** `/对账`：全量格·切满探针对读表 + 全量落成对账表（真源比例、快照、切满探针、
  切满差额、全量格、结论、可核、回执、审计证据数、名册一致、实例全切、切流比例、缺口标），
  每行「重放收口」+ 顶部「一键重放收口」全部已放行单。
- **健康** `/健康`：切流比例、金丝雀真源、未满百标、全量格、切满探针、回执号列（挂接行与环境旁读同源）。
- **审计** `/审计`：类别/关键词/关联编号过滤表单（查询参数直连后端）。

### 夹具与自检

服务端夹具场景（每个场景建独立命名的专用应用，避免同应用在途单互斥）：

```text
POST /api/夹具/未满百全量
POST /api/夹具/满百全量
POST /api/夹具/并发改比例
POST /api/夹具/半截
POST /api/夹具/原子失败
POST /api/夹具/回执绿比例未满        # 回执绿 + 比例未满：全量格不得亮
POST /api/夹具/比例满全量标缺        # 比例满 + 错挂未满百标：全量格不得写未满百
POST /api/夹具/全量格与旁侧格双拧    # 全量格与旁侧计数格不得各自拧花
POST /api/夹具/全量与日常放行旁路半截 # 旁路写口半截：钉缺口 + 重放收口
POST /api/夹具/套件
```

四路分测（本事故夹具）：`回执绿比例未满`、`比例满全量标缺`、`全量格与旁侧格双拧`、
`全量与日常放行旁路半截`，可单独 `--scenario` 复现。

命令行：

```bash
cd backend
/tmp/venv/bin/python run_fixtures.py                      # 隔离临时库直跑全套，全过退出 0
/tmp/venv/bin/python run_fixtures.py --scenario half       # 单场景
/tmp/venv/bin/python run_fixtures.py --base-url http://127.0.0.1:11800
                                                           # 对已起服务走 HTTP 夹具端点
# 报告写 backend/fixtures/report.json
```

测试：

```bash
cd backend
/tmp/venv/bin/python -m pytest tests/ -q
# 17 passed：未满百到处留标、种子 10% 单全量、满百干净、晋升到产同闸、
# 并发、校验/冻结、故障回滚、种植半截的检测+重放、幂等、夹具套件、策略声明；
# 本事故四路：回执绿比例未满不亮全量格、比例满标缺不写未满百、全量格与旁侧格同源、
# 旁路半截钉缺口并重放收口、重放揭穿假全量回执
```

前端生产构建：

```bash
cd frontend && npm install && npm run build
```

### 边界说明

本次只做「全量落成闸」。比例字段以 `releases.canary_ratio` 为现成真源列并提供唯一写口；
更广义的「比例字段真源/溯源」是独立任务，本改动通过 `金丝雀对账`（真源比例 vs 回放比例 vs
落成快照）保持接口松耦合，不把两套机制焊死。
